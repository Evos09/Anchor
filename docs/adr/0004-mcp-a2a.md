# ADR-0004: MCP and A2A spec versions and SDKs (§17 Q4)

- Status: Proposed — pending evaluation
- Date: 2026-10-06

## Context

The Coordination Hub (Phase 4) exposes MCP and A2A endpoints. The spec says
to verify current spec versions and SDK maturity before choosing.

## What was observed (2026-10-06)

- The specification sites (`modelcontextprotocol.io`, `a2a-protocol.org`)
  were **unreachable** from the build environment (egress policy). Spec
  versions could therefore **not be verified** and none is pinned here.
- crates.io API: `rmcp` 3.5.1, published 2026-10-05, with repository field
  `github.com/modelcontextprotocol/rust-sdk`. A repository field is
  self-declared, so this does not by itself prove official ownership.
- npm: `@modelcontextprotocol/sdk` 1.32.1 (MIT).
- crates.io search for "a2a" returned only third-party crates (`a2a`,
  `a2a-rs-core`, `a2a-agents`, `apcore-a2a`, `inference-gateway-adk`,
  among others). None was identifiable as an official SDK.

## Decision (direction)

- **MCP**: evaluate `rmcp` through all five §0 steps. Ownership must be
  confirmed against the MCP organisation's own site. If it fails any step,
  implement the server subset we need from the pinned spec.
- **A2A**: implement from the spec. Pin the version once the spec can be
  fetched and read, and document every deviation. No third-party A2A crate
  is adopted.
- Hub transport is local only (Unix socket / named pipe) and requires
  authentication even locally (§6.5). That requirement is independent of
  either protocol version.

## Blocking items

1. Fetch and read both specifications; pin versions in this ADR.
2. Run the five-step record for `rmcp`.
